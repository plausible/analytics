## 6. Not mapped

Proposed scope `none` in the tables above means session only, never grantable to tokens. These entry points have no block at all:

| Entry points | Why |
|---|---|
| Registration, login, activation, password reset, 2FA setup and verification, SSO login and SAML, logout | Authentication flows: they establish a session, they are not actions on a resource |
| OAuth authorize, token and /.well-known metadata | They issue credentials; the capabilities are on the resources the credentials reach |
| POST /api/event, GET /api/error | Tracker ingestion, public by design |
| /api/paddle/webhook, /api/postmark/webhook, /api/paddle/currency | Third-party webhooks and billing helpers |
| /api/health, /api/system/* | Health checks |
| /flags/*, /debug/clickhouse | Super admin tooling outside customer support (feature flags UI, ClickHouse debug) |
| /helpscout/* | Support integration authenticated by HelpScout |
| /dev/*, /plug-tests/*, /e2e-tests/*, /sent-emails* | Dev, test and e2e only |
| Pages that load no data beyond a mapped read: new site, new API key, *_form, danger zones, settings_visibility, settings_shields, preferences, the settings index redirects | Reads are mapped on the handler that loads the data (controller action or LiveView mount/update), not per page |
| Billing pages (choose plan, upgrade, previews, ping) and the ChoosePlan LiveView | Billing is never grantable to tokens; get_subscription and change_plan are mapped |
| Avatar, error report, GET / | Not actions on a resource |
| Plugins API /spec/* and /v1/capabilities, GET /api/docs/query/schema.json | Public metadata |
| MCP server/discover and tools/list | Protocol methods, not capabilities |
| UI-only LiveView events (filter, sort, modals, CTA dismissals, form validation) | Change only the LiveView's own state |
